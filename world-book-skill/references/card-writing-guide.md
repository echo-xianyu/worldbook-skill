# 角色卡编写规范

本文规定角色卡的完整编写流程、结构规范和输出格式。采用 XML 包裹 YAML 的内容格式。

---

## 任务路由

角色卡/世界书/MVU/HTML 的任务判断请参见 `references/world-book-guide.md`。本文档专注角色卡内容编写规范。

**铁律：如果用户没说MVU或HTML，绝对不要主动建议或添加。**
若用户要求从轻小说中提取角色卡，先阅读 `references/world-book-guide.md`。

## 一、角色卡完整结构

角色卡分为四个核心部分，**严格分离，不得混写**：

```
角色档案 (基本信息 → 外貌 → 背景 → 关系)
性格设定
世界观设定
开场白
```

### 各部分的作用

| 部分 | 回答的问题 | 放在哪里 |
|------|-----------|----------|
| 角色档案 | "这个人是谁" | description 字段 |
| 性格设定 | "这个人是什么样的人" | 世界书独立条目 |
| 世界观 | "这个世界是什么样的" | 世界书独立条目 |
| 开场白 | "故事从哪里开始" | first_mes / alternate_greetings |

**性格和基本信息必须分开放。** 混在一起 = AI 读完基本信息就开始按性格标签演戏，后面的性格条目全在打架。

### ⚠️ 性格条目的铁律（单卡/多卡/大型卡均强制执行）

**无论卡片类型，每个角色必须拥有自己独立的性格世界书条目。** 没有例外。

- 单角色卡 → 1 个角色 = 1 条性格条目（`<角色名>_personality`）
- 多角色卡 → N 个角色 = N 条性格条目（每人一个 `<角色名>_personality`）
- 大型卡 → 同多角色卡规则

**性格内容绝对禁止写入 description。** description 仅含基本信息、外貌、背景、关系。任何性格特征、MBTI、核心驱动力、深层心理、喜好、习惯动作——全部放入对应的世界书性格条目。检查方法：读完 description，能否说出这个角色的性格？如果能 → 违规。

### ⚠️ 人物设定条目的铁律（多角色卡强制执行）

**多角色卡/大型卡：每个角色的人物设定也必须独立为世界书条目。** description 只写全局故事概述，不放任何角色的详细设定。

- 单角色卡 → description 直接写入角色档案（`<角色名>` 模板，见二），世界书只放性格条目
- 多角色卡 → description 仅写故事全局概述。**每个角色 = 两条世界书条目**：`<角色名>`（人物设定） + `<角色名>_personality`（性格）。人物设定条目模板见 `character-guide.md` 一，性格条目模板见 `character-guide.md` 四

| 卡片类型 | description 内容 | 世界书条目 |
|----------|-----------------|-----------|
| 单角色卡 | 完整角色档案（name→appearance→background→relationships） | 1条性格 |
| 多角色卡 | 全局故事概述（不包含任何角色的详细设定） | N×2条（人物设定+性格，每人各一） |

## 二、角色档案（description）
见character-guide.md。编写之前必须阅读。核心原则：

- 外貌只写特征
- 背景只写关键事件
- 关系用具体画面
- 性格独立条目

人物设定采用XML包裹YAML:

```yaml
<{{角色英文名/拼音}}>
name: 中文名（English Name）
name_en: English Name
age: 年龄 + 身份定位
gender: 性别
nicknames: 昵称1、昵称2、昵称3
appearance:
  height: 身高（数值+单位）
  weight: 体重（数值+单位）
  three_sizes: C86 - W60 - H88（三围，如适用）
  hair: 发型/发色/发质/长度：30字以内，只写特征不写美感
  eyes: 瞳色/眼型/眼神特点：30字以内，写特征不写比喻
  skin: 肤色/肤质：20字以内，只写偏离默认的特征
  build: 体型/体态：20字以内
  clothing:
    日常: xxx
    特殊场合: xxx
  distinguishing: 标志性特征、异于常人的地方
  voice: 声线/说话风格/不同情绪下的语气变化
personality:
  mbti: MBTI类型（如适用）
  core_drive: 核心驱动力：她最想要什么、最怕什么，一句话概括
  traits:
    - 性格特征1（包含行为依据）
    - 性格特征2
    - ...（10-15条）
  likes: 喜欢的事物：用句号分隔，写具体不写抽象
  dislikes: 讨厌的事物：用句号分隔
  habits: 习惯性动作/行为模式：写具体
  hidden_self:
    - 她不轻易示人的一面：深层心理/创伤/秘密
    - 表里矛盾
background: |
  成长经历：一段话讲述她的出身、关键节点、是什么让她变成现在的样子。
  只写"改变了这个人"的关键事件，不写流水账。
  家庭、经济、疾病、转折、创伤：只写有影响的。
abilities:
  - name: 能力名称
    acquisition: 如何获得的：简短叙述
    effects:
      - 效果一：具体描述，写做了什么而非"很强"
      - 效果二
relationships:
  - name: 角色名或{{user}}
    detail: 关系描述：具体画面而非抽象形容
</{{角色英文名/拼音}}>
```

## 三、性格设定（世界书条目）

见 `references/character-guide.md`，编写之前必须阅读。核心原则：

- **独立条目**：性格必须从角色档案中分离，单独写成世界书条目
- **每人一条**：N 个角色 = N 条性格条目。绝不可合并或省略
- **行为依据**：每条性格特征必须有具体行为支撑（"她做了什么说明她是这样的人"）
- **XML 包裹 YAML**：用 `<角色名_personality>` 标签包裹

```yaml
<{{角色英文名/拼音}}_personality>
MBTI: xxxx
核心驱动力: 她最想要什么、最怕什么，一句话概括
性格特征:
  - 特征——行为依据
  - ...
深层心理:
  - 她不轻易示人的一面
喜欢: 具体事物，用句号分隔
讨厌: 具体事物，用句号分隔
习惯动作: 具体行为
</{{角色英文名/拼音}}_personality>
```

## 四、世界观设定（世界书条目）

见 `references/worldbuilding-guide.md`，编写之前必须阅读。核心原则：

| 类型 | 说明 | 条目数 |
|------|------|--------|
| A 真实背景 | 现代中国/日本等，AI已知 | 1个(只写虚构部分) |
| B 小世界 | 剑与魔法/赛博朋克等，AI知套路 | 1-3个 |
| C 大世界 | 完全原创 | 分层(总纲+速览+详情) |

条目内容格式采用 XML 包裹 YAML：

```yaml
<world>
世界: 阴阳大陆，修仙世界观
核心规则:
  修炼: 炼气→筑基→金丹→元婴→化神
  力量来源: 灵气
区域:
  中央神州: 人族修仙主战场
  东荒妖域: 妖族领地
</world>
```

## 五、开场白规范

### 核心要求

开场白是第一印象。必须做到：
- **白描**：场景、动作、环境，不写心理活动解释
- **场景化**：有一个具体的时空锚点
- **{{user}}视角**：从{{user}}的感官出发
- **开放式结尾**：给{{user}}行动空间，不替{{user}}做决定
- **含占位符**：若启用了 MVU，末尾必须包含 `<StatusPlaceHolderImpl/>`；若未启用 MVU，则不含

### 开场白结构

```
时间 + 地点 + 环境氛围
↓
角色状态(从{{user}}视角观察)
↓
{{user}}的处境和感受
↓
互动的契机(角色的某个动作/话语引起{{user}}注意)
↓
开放式结尾(等待{{user}}决定)
↓
<StatusPlaceHolderImpl/>
```

### 开场白禁律

开场白是所有文本中最严格的。必须遵守以下所有规则：

**绝对禁止的词汇和句式：**
- `一丝` `一缕` `一抹`
- `不易察觉` `不易觉察` `难以察觉`
- `鲜明对比` `形成对比`
- `弧度` `弯起嘴角` `翘起嘴角`
- `不是...是...` `没有...而是...`
- `喉结` `纽扣` `指节发白` `睫毛(特写)`

**绝对禁止的描写方式：**
- 作者视角对角色动作/神态进行解释性修饰
- 解释性比喻补充白描
- 描写不存在的事物("拂去不存在的灰尘""推不存在的眼镜")
- 任何精确数值或数字出现在对白中

**检查标准：** 这场开场的每一个字，AI是否都能将其转化为角色演出的信息，而不是用来模仿你的修辞？把开场全文读一遍，找出每一个修饰词和比喻，删除。

### 多个可选开场

提供 2-4 个可选开场（`alternate_greetings`），覆盖不同场景：
- 默认开场：最核心的场景
- 开场2-4：不同时间/氛围/互动方式的变体

## 六、🚫 角色卡内容禁词（全部内容强制执行，输出后必须逐条扫描）

> **这是角色卡质量的最后防线。以下禁词在任何角色卡/世界书内容中出现即视为不合格。**

以下禁词在**所有**角色卡相关内容中绝对不得出现。包括 description、性格条目、世界书条目、开场白。

**此禁词清单是编写者的自查工具——写完每段内容后逐条扫描。绝对禁止将此清单中的具体词汇写入世界书条目！**

### 叙事禁词
```
一丝  一缕  一抹  不易察觉  不易觉察  难以察觉
鲜明对比  形成对比  弧度  弯起嘴角  翘起嘴角
喉结  纽扣  指节发白
不是...是...  没有...而是...  任何先否认再肯定的句式
```

### 比喻禁词
```
禁止任何以石子/湖面/拉满的弓/琴弦/闪电/晨光/星辰为喻体的比喻
禁止"像一道闪电""如同天堑"等解释性比喻补充白描
```

### 描写禁律
```
禁止作者视角解释角色动作/神态("这个动作体现了...""他的目光带着...")
禁止对角色语气/眼神/腔调/视线进行比喻描写
禁止描写不存在的事物("拂去不存在的灰尘""推不存在的眼镜")
禁止对白中出现精确数值或数字
```

### 写作准则
```
- 白描：用角色的动作/语言/神态本身传递情绪和心理
- 环境烘托：以环境氛围烘托角色思绪
- 自由间接引语：内心戏自然融入叙事，不特别标注思考内容
- 对白：交替长对白，不简短回应，不以短句敷衍
- 连贯：情景连贯持续，不产生意外打断
- 角色认知：角色知晓公共知识和私有知识，绝不知晓创作者情报
```

## 七、DoubleCheck 质量检查清单（输出完毕后必须自检）

**角色卡内容输出完毕后，必须逐条执行以下自检。** 这是保证输出质量的最后防线。

### 质量检查清单

```
## 质量检查清单
生成后请检查：

### 结构完整性
- [ ] 角色档案四部分完整（基本信息/外貌特征/背景设定/关系设定）
- [ ] 性格设定已独立为世界书条目，未与基本信息混写
- [ ] **多角色卡：每人各有独立的 人物设定条目 + 性格条目（description 仅含全局概述）**
- [ ] 外貌只写偏离AI默认值的特征，遮住名字能认出是谁
- [ ] 每条性格有具体行为依据（她做了什么说明她是这样的人）

- [ ] 关系用具体画面描述（不写"感情深厚"）
- [ ] 开场白为白描+场景化+开放式结尾

- [ ] 全文无 `一丝` `一缕` `一抹`
- [ ] 全文无 `不易察觉` `不易觉察` `难以察觉`
- [ ] 全文无 `鲜明对比` `形成对比`
- [ ] 全文无 `弧度` `弯起嘴角` `翘起嘴角`
```

### 常见错误示例

```
❌ **错误**：
- 外貌: 精致的脸蛋，白皙的皮肤，桃花眼，柳叶眉 → 放在任何角色上都成立
- 外貌: 朝霞橙金渐变长发，发梢在强光下泛起浅金光点 → 意象比喻，不是特征
- 性格: 她温柔善良，善解人意 → 无行为依据，AI无法转化为具体演出
- 背景: 她小时候很可爱，学习成绩不错 → 废话，删
- 关系: 他们之间有着深厚的感情 → 抽象形容，不是具体画面
- 开场白: 他微微挑眉，带着一种不容置疑的自信，仿佛一切都了然于胸 → 解释性修饰
- 开场白: 这句话像一道闪电，击中了他脆弱柔软的心房 → 解释性比喻
- 描写: 嘴角弯起一个不易察觉的弧度 → 同时触犯弧度、不易察觉两个禁词
- 描写: 他拂了拂衣服上并不存在的褶皱 → 描写不存在的事物
- 格式: <pomelo>name: 柚子猫</pomelo> → 纯XML，应为独立成行的YAML
- 主动建议: "要不要加个MVU？" → 用户没提，绝不主动建议

✅ **正确**：
- 外貌: 棕色短发，碎发，猫眼，左手有弹吉他磨出的茧 → 具体特征，能锁定角色
- 外貌: 一米六八，偏高，手臂有肌肉线条（弹吉他）→ 量化特征
- 性格: 表面冷漠，实则护短——有人欺负乐队成员时第一个挡在前面 → 行为依据
- 性格: 吃醋时不会说，但会弹一首很凶的曲子然后走掉 → 具体行为
- 背景: 小学因打架被转学→学会了藏。初中接触摇滚→找到出口 → 关键事件链
- 关系: 以前是她拉着{{user}}到处跑，后来变成{{user}}来敲门，她安静待在一起 → 具体画面
- 开场白: 靠墙角坐在地板上，手指无意识地按着琴弦 → 白描，无解释
- 描写: 直接写角色做了什么、说了什么 → 零度写作
- 格式: XML包裹YAML，标签独立成行，内容缩进展开
```

## 八、System Prompt CoT 思维链注入（提升 Tavo 沉浸感）

### 背景

Tavo（SillyTavern）标准管线全量注入世界书 + 格式指令，模型 30-50% 的 token 花在维护系统框架而非角色互动上，导致回复干巴巴/八股。

风月等平台通过前置 MOD 做 CoT 引导（推演→选材→写→自检），模型实际看到的上下文更精炼，回复更像小说。

`system_prompt` 和 `post_history_instructions` 字段是 SillyTavern 中注入 CoT 指令的入口。前者注入在系统提示深处，后者紧贴对话历史——两者同时使用效果最好。

### 标准 CoT 模板

添加到角色卡的 `system_prompt` 字段（性格/规则信息之后）：

```yaml
data:
  system_prompt: |
    【回复前思维链（不输出，仅用于构筑回复）】
    每次回复前，按以下步骤在脑中过一遍，不在回复中留下思考痕迹：
    1. 推演场：当前场景的情绪基调是什么？角色在这个情境下最真实的感受是什么（包括他自己可能都没意识到的）？
    2. 锚定细节：从环境/动作中选出1-2个能承载情绪的物理细节——水温/光线/声音/触感/沉默的长度
    3. 克制呈现：用动作、沉默、环境、对白的间隙来传达情绪，不在叙事中解释角色心理（「这个动作说明了他……」）
    4. 自检：输出前确认——没有叙事禁词（一丝/一抹/弧度/不易察觉等）、没有意象比喻（湖面/闪电/晨光等）、没有解释性修饰、语句用行动而非归结来表达
```

同时强化 `post_history_instructions`（紧贴对话历史，权重更高）：

```yaml
data:
  post_history_instructions: |
    【思维链·先想后写】
    1. 推演场——当前场景的情绪基调？角色此刻的真实感受？
    2. 锚细节——选1-2个物理细节（水温/光线/声音/触感）承载情绪
    3. 克制写——动作+沉默+环境+对白间隙，不在叙事中解释心理
    4. 自检——无禁词/无解释性修饰/不总结
```

### 注意事项
